# Scanrail 0.2.0 Release Notes

Release date: 2026-06-25

Scanrail 0.2.0 starts the v0.2 web/API expansion track with a conservative native TLS baseline scanner. It keeps broader DAST and API fuzzing behind future safety gates while adding a useful HTTPS check that works without Docker.

## What Changed

- Added `scanrail run --only tls` for HTTPS certificate and protocol baseline checks.
- Added the native `tls` scanner to generated `quick` profiles after `gitleaks` and `headers`.
- Added TLS findings for untrusted certificate chains, hostname mismatches, expired or soon-expiring certificates, and negotiated TLS versions below 1.2.
- Updated JSON/HTML report rendering so high and critical findings have explicit severity styling.
- Updated README, npm package README files, CLI/config/safety docs, tool review, risk docs, and release notes for the 0.2.0 scanner surface.

## Safety Notes

The native TLS scanner opens one TLS connection to an HTTPS target and sends no HTTP request payload. It is still classified as `interactive` because it touches a network target, but it does not crawl, fuzz, follow redirects, or run attack templates.

MCP execution remains intentionally limited to the native headers scanner in this release. Extending MCP scanner execution beyond headers still requires additional audit, target-boundary, and host-compatibility work.

## Compatibility

Existing `scanrail doctor`, `scanrail init`, `scanrail setup`, `scanrail run --only headers`, `scanrail run --only gitleaks`, `scanrail run --profile quick`, and `scanrail mcp serve` workflows remain compatible. Newly generated `quick` profiles include `tls`; existing `scanrail.yaml` files keep their current tool list until users edit or regenerate them.

## Non-Goals

This release does not ship OWASP ZAP, Nuclei, Schemathesis, Trivy, Semgrep, SBOM generation, SARIF, testssl.sh, active DAST, or broader MCP scanner execution. It also does not claim commercial scanner parity.
