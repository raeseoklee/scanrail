# Scanrail 0.1.3 Release Notes

Release date: 2026-06-15

## Summary

Scanrail 0.1.3 is a release-readiness and safety hardening patch. It does not expand the scanner engine surface. It makes the existing native headers and MCP MVP safer to verify, easier to audit, and clearer to release as OSS.

## Highlights

- MCP active-scan attempts now leave local audit evidence.
- MCP Workbench verification is part of the documented regression path.
- Scanner target redaction is centralized so reports and logs avoid raw target leakage.
- Scanner capability metadata makes safety enforcement gaps explicit instead of implicit.
- The release risk register now maps remaining risks to release, MCP expansion, scanner adapter, and roadmap gates.
- The public docs now include a release checklist and release treatment plan for npm publishes.

## User Impact

Existing `scanrail doctor`, `scanrail init`, `scanrail setup`, `scanrail run --only headers`, and `scanrail mcp serve` workflows remain compatible. Users installing through npm receive the same CLI surface with stronger audit and safety documentation behind it.

## Verification

The release prep expects these gates before publishing:

```bash
npm run docs:check-links
npm test
make release-dry-run
npm run publish:dry-run
```

The npm publish workflow should still be run through GitHub Actions in this order:

```text
validate -> dry-run -> publish
```

## Non-Goals

This release does not ship Docker-backed Gitleaks, Trivy, Semgrep, or OWASP ZAP adapters. It also does not promote SARIF output to a stable report format. Those remain scanner adapter and reporting expansion gates.
