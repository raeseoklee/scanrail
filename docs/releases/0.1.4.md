# Scanrail 0.1.4 Release Notes

Release date: 2026-06-16

Scanrail 0.1.4 expands the MVP from a native headers-only scanner into the first real multi-scanner run path. It adds a Docker-backed Gitleaks adapter while keeping the safety model conservative for scanners that are not ready yet.

## What Changed

- Added `scanrail run --only gitleaks` for local secrets scanning through `ghcr.io/gitleaks/gitleaks:v8.30.1`.
- Added a shared Docker runner abstraction for scanner adapters.
- Normalized Gitleaks findings into the shared report model with `tool`, `evidence`, and remediation fields.
- Added tool metadata to JSON and HTML reports, including scanner version, image, and redacted raw artifact path.
- Redacted Gitleaks raw artifacts before persisting them under `.scanrail/raw`.
- Updated generated quick profiles to include `gitleaks` and `headers`.

## Safety Notes

Gitleaks is treated as a passive local workspace scanner. It mounts the workspace read-only and writes scanner output to the Scanrail raw artifact directory. Secret values and matched snippets are redacted before normalized reports or raw artifacts are persisted.

Trivy and Semgrep remain disabled behind the production-readiness gate. Explicitly selecting an unready scanner still fails with safety exit code `5`.

## Compatibility

Existing `scanrail doctor`, `scanrail init`, `scanrail setup`, `scanrail run --only headers`, and `scanrail mcp serve` workflows remain compatible. The MCP MVP still exposes the native headers scan only; Gitleaks MCP execution is intentionally deferred.

## Non-Goals

This release does not ship Trivy, Semgrep, SARIF, or broader MCP scanner execution. It also does not claim commercial scanner parity.
