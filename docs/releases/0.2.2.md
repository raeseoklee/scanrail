# Scanrail 0.2.2 Release Notes

Release date: 2026-06-29

Scanrail 0.2.2 continues the v0.2 web/API expansion track by making documented target safety settings executable before adding heavier active scanners.

## Added

- Added shared web target guardrail validation for native interactive scanners.
- Added runtime parsing for `targets.web.exclude_paths`, `safety.blocked_paths`, `safety.require_allowlist`, and `safety.max_rps`.
- Added safety tests for allowlist host/port matching, wildcard host matching, required allowlists, and blocked path matching.

## Changed

- Native `headers` and `tls` scans now reject targets outside `targets.web.allowlist` when allowlist enforcement is enabled.
- Native `headers`, native `tls`, and MCP-triggered headers scans now reject target paths matching `targets.web.exclude_paths` or `safety.blocked_paths` before network contact.
- Interactive scanner capability requirements now include `blocked_paths`; native `headers` and `tls` declare that capability through Scanrail preflight enforcement.
- MCP config resources now expose redacted guardrail fields so clients can inspect the active safety boundary.

## Safety Boundary

This release does not add ZAP, Nuclei, Schemathesis, or other active scan engines. It prepares the guardrail layer those adapters need by enforcing target scope before existing native interactive scanners run.
