# Scanrail 0.1.4 릴리스 노트

릴리스 일자: 2026-06-16

Scanrail 0.1.4는 MVP를 native headers 전용 scanner에서 첫 multi-scanner 실행 경로로 확장합니다. Docker 기반 Gitleaks adapter를 추가하되, 아직 준비되지 않은 scanner에는 보수적인 safety gate를 유지합니다.

## 변경 사항

- `ghcr.io/gitleaks/gitleaks:v8.30.1`을 사용하는 local secret scan용 `scanrail run --only gitleaks`를 추가했습니다.
- scanner adapter용 공통 Docker runner abstraction을 추가했습니다.
- Gitleaks finding을 공통 report 모델의 `tool`, `evidence`, remediation 필드로 정규화했습니다.
- JSON/HTML report에 scanner version, image, redacted raw artifact path를 포함하는 tool metadata를 추가했습니다.
- `.scanrail/raw`에 저장하기 전에 Gitleaks raw artifact를 redaction합니다.
- 생성되는 quick profile이 `gitleaks`와 `headers`를 포함하도록 갱신했습니다.

## 안전 메모

Gitleaks는 passive local workspace scanner로 취급합니다. workspace는 read-only로 mount하고 scanner output은 Scanrail raw artifact directory에 기록합니다. secret value와 matched snippet은 normalized report 또는 raw artifact를 저장하기 전에 redaction합니다.

Trivy와 Semgrep은 production-readiness gate 뒤에 disabled 상태로 남아 있습니다. 준비되지 않은 scanner를 명시 선택하면 계속 safety exit code `5`로 실패합니다.

## 호환성

기존 `scanrail doctor`, `scanrail init`, `scanrail setup`, `scanrail run --only headers`, `scanrail mcp serve` 흐름은 호환됩니다. MCP MVP는 여전히 native headers scan만 노출하며, Gitleaks MCP 실행은 의도적으로 다음 단계로 미룹니다.

## 비목표

이 릴리스는 Trivy, Semgrep, SARIF, broader MCP scanner execution을 제공하지 않습니다. 상용 scanner parity도 주장하지 않습니다.
